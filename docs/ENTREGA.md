# Prazo, entrega e avaliação

## Prazo

**6 dias corridos** a partir da disponibilização do desafio. O avaliador informará a data e o horário exatos de encerramento.

## Cronograma sugerido

| Dia | Atividade |
| --- | --- |
| 1 | Ambiente, repositório, branch e estrutura Next.js |
| 2 | Exploração da API e coleção Postman |
| 3 | Integração GET e listagem de tarefas |
| 4 | Pesquisa, filtros, cadastro e mudança de status |
| 5 | Exclusão, tratamento de erros, interface e testes |
| 6 | README, revisão, push e Pull Request |

O cronograma é orientativo: a entrega será avaliada pelo resultado e pelo processo.

## O que entregar

1. Branch individual publicada no repositório.
2. Pull Request aberto **para `main`**, com resumo das funcionalidades implementadas.
3. Código-fonte executável, com instruções no README.
4. Coleção Postman exportada em JSON.
5. Relato breve de dificuldades e de funcionalidades pendentes, se houver.

**Não faça merge do Pull Request.** Aguarde a revisão do avaliador.



## Apresentação

Após a entrega, haverá uma conversa técnica individual de aproximadamente 15 a 20 minutos para demonstrar a aplicação e explicar decisões de implementação, Git e integração com API.

É permitido consultar documentação, tutoriais e IA durante o desafio, mas o candidato deve compreender e conseguir explicar a solução entregue.
